三、P0 修复详述：编辑污染部分平仓链结算字段

问题复现

编辑弹窗保存（saveEditLog）对任何已平仓记录都会执行 calculateCloseSettlement(item, closePrice) 并无条件覆盖 pnlAmount / rMultiple / pnlPercent / grossPnlAmount。该函数用 item.positionSize 计价——部分平仓链上：

  • 中间态（已平 50%，positionSize=剩余 500）：结算按剩余仓位全量计价 → 实测 pnlAmount 8.33 → 6.33、rMultiple 0.42 → 0.63，且 realizedPnl 仍为 8.33（不同步）→ 后续最终平仓的累计、胜率、R 统计全部基于污染数据。
  • 最终平仓（positionSize=0）：结算函数因仓位 ≤0 返回 null → 保存被拦"编辑后的平仓结算无效"→ 用户完全无法编辑该记录（改备注/补亏损原因/修正平仓价都不行）。

修复方案

_partialChain = closes 数组长度 > 1 || closeType ∈ {partialTP, reducePosition} || positionSize ≤ 0
→ 命中则跳过自动重算（保留整笔累计口径与表单值）
→ 全新平仓记录（从未部分平仓）保留自动重算（改价同步 PnL 的原始功能）

同时修复 emRecalc：已全部平仓（positionSize ≤ 0）时不再重算预览，避免显示"-费用"误导。

实测证据（浏览器）

场景修复前修复后
中间态编辑保存pnlAmount 8.33→6.33（污染）保持 8.33，realizedPnl=8.33 一致
最终平仓编辑保存被拦"结算无效"正常保存，pnlAmount=18.33 保持
全新平仓编辑（改价）自动重算自动重算仍生效（原始功能未破坏）

四、P1 修复详述：成本侵蚀指标低估费用

成本侵蚀 = Σ手续费 ÷ Σ毛盈亏绝对值。原实现读取 item.fee——部分平仓时该字段被按比例缩减为剩余仓位的 round-trip 费，而整笔累计费用记录在 realizedFee。部分平仓链只统计最终平仓记录 → 费用被低估约一半。

修复：优先取 realizedFee（部分平仓链已实现费用累加），无则回退 item.fee（兼容旧数据）

实测证据（浏览器）

部分平仓链最终平仓记录（item.fee=1.0、realizedFee=2.0、pnlAmount=18.33）：
修复前：费用按 1.0 → 5.5% ｜ 修复后：总手续费 2.00 U / 毛盈亏 18.33 U = 10.9% ✓
